# Hackathon evidence

`hackathon-evaluation.json` is generated by an actual local run of:

```text
BRAVON_RUNNER_HMAC_KEY_HEX=<private-32-byte-key> \
  python -m proofops.hackathon_eval \
  --output docs/evidence/hackathon-evaluation.json
```

The report separates offline first-party fixture execution from Meta inference.
`NOT_RUN` means no model request occurred; it is not a simulated AI result.

Each result contains an HMAC evidence envelope bound to the immutable Docker
image identifier and canonical verification-report digest. The runner key is
intentionally excluded from Git. HMAC proves possession of that private key and
detects tampering; it is not public-key attestation or proof that the runner was
organizationally independent.

The `local-meta-*.json` files are actual local `llama3.1:8b` runs through
Ollama. Files without a verification object are genuine abstentions, retained
rather than rewritten as successes. Trial 3 for the software case and trial 2
for the data case contain model-proposed repairs subsequently accepted by the
independent Docker verifier. The model request never contains the hidden test;
the report includes its filename only in the later runner-owned verification
section.

The infrastructure run is also actual local Meta inference. Its proposed edit
fixed the visible health-path regression but left two unsafe deployment settings
unchanged, so independent behavior tests rejected it as `REJECTED_FALSE_GREEN`.

Llama 3.1 is a Meta open-weight model and incurs no API cost. The Participant
Guide specifically promotes Muse Spark Open for this event, so these runs do
not claim to be Muse results. Baseten's required model identifier remains
`meta-models/muse-spark-open-1026` if authorized partner access is later
confirmed.

`meta-evaluation.json` is generated from those immutable run files by
running:

```text
python -m proofops.hackathon_eval \
  --meta-evidence-root docs/evidence \
  --output docs/evidence/meta-evaluation.json
```

Its rubrics are included in the report. In particular,
the abstention-quality score is intentionally zero because all three abstentions
used “Not applicable” instead of explaining uncertainty. Three fresh timed runs,
one per domain, retain reproduction, model-investigation, and candidate-verifier
duration and provide the end-to-end benchmark. Older version 1 runs remain in
the history but are excluded from that total.
